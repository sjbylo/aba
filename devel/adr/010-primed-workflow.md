# ADR 010: Primed workflow (DevOps / hands-off deployment)

## Status: Accepted

## Context

In DevOps environments, ALL cluster configuration is known in advance on the
connected side — generated by an external pipeline, tool, or manual preparation.
The user wants to "prime" the bundle with fully pre-configured cluster directories
so that deployment on the disconnected side is a single command with no interactive
steps.

Additionally, ABA's `cluster.conf`-driven agent-config.yaml generation does not
yet support per-node `rootDeviceHints` or per-role NIC names (see BACKLOG). The
`--primed` workflow lets users supply their own byte-for-byte agent-config.yaml,
bypassing ABA's generation.

Future: container image delivery (Podman) will leverage the same primed configs.

## Decision

Three-command "primed family":

| When   | Command                            | Alias            | Purpose                             |
|--------|------------------------------------|------------------|-------------------------------------|
| Day 0  | `aba bundle --primed`              | `aba bundle-primed` | Full bundle with pre-configured dirs |
| Day N  | `aba transfer-primed`              | `aba transfer`   | Lightweight configs-only tar        |
| Disco  | `aba -d <cluster> deploy-primed`   | `aba -d <cluster> deploy` | One-command pipeline     |

### Key design choices

1. **`.primed` marker**: Placed in cluster dirs that have both `install-config.yaml`
   and `agent-config.yaml`. Tells Make to skip `agent-config.yaml` regeneration.
   `install-config.yaml` is ALWAYS regenerated (needs disco registry CA).

2. **Separate transfer tar (Option B)**: `aba-transfer-configs.tar` for cluster dirs
   is separate from `aba-transfer.tar` (ISC/CLIs). Both live in `mirror/data/` so
   `cp mirror/data/*.tar` still works. No overwrite conflict.

3. **deploy-primed is a simple chain**: No new state mechanism. Leverages Make's
   existing marker-file idempotency. Steps: mirror install → mirror load → cluster
   install → day2.

4. **`aba bundle-primed` alias**: Equivalent to `aba bundle --primed`. Added for
   consistent naming across the primed family.

## Consequences

- New scripts: `deploy-primed.sh`, `transfer-primed.sh`
- New marker: `.primed` (already existed in backup.sh, now formalized)
- New artifact: `mirror/data/aba-transfer-configs.tar`
- New CLI targets in `aba.sh`: `deploy-primed`, `deploy`, `transfer-primed`,
  `transfer`, `bundle-primed`
- `reg-load.sh` handles config-only transfers (no `mirror_*.tar` present)
- Help files: `others/help-deploy.txt`, `others/help-transfer.txt`
